## 项目描述（全栈开发 + 自测版）

> 独立完成情侣专属移动端 Web 应用 **Our Space** 的全栈开发与测试工作，涵盖需求分析、架构设计、前后端编码、测试验证到部署上线全流程。项目包含 **7 大功能模块**、**7,157 行** 代码、**31 个** 组件、**9 个** 自定义 Hook，开发周期仅 **3 天**，借助 AI 辅助效率提升 **5-8 倍**。

### 一、全栈开发职责

**1. 前端架构与核心开发**
- 基于 **React 19 + TypeScript** 搭建项目，配置 Vite + Tailwind CSS v4 + 路径别名等工程化方案
- 设计 **Demo 模式（localStorage）** 与 **Supabase 云端模式** 双轨架构，开箱即用且支持无缝切换
- 封装 `useNotes`、`usePhotos`、`useTimeline`、`useWishes`、`useTimeCapsules` 等 **9 个** 自定义 Hook，统一管理业务逻辑与状态
- 抽离 Toast、Skeleton、ErrorBoundary、LazyImage、AuthorBadge、PullToRefresh 等 **6 个** 通用 UI 组件，组件复用率 > 60%
- 实现 **React.lazy + Suspense** 路由级代码分割，首屏加载体积减少约 40%

**2. 后端设计与数据层开发**
- 基于 **Supabase** 设计并实现 **7 张核心数据表**（notes、photos、countdowns、timeline_events、wishes、time_capsules、app_settings）
- 编写完整 **SQL 建表脚本**，包含字段约束、CHECK 校验（如 created_by IN ('he', 'she')）、索引设计
- 配置 **Row Level Security (RLS)** 策略，确保数据访问安全
- 设计 **Storage 存储方案**，实现照片上传/删除/获取公开 URL 完整流程
- 前端封装统一的数据访问层（9 个自定义 Hook），屏蔽 demo 与真实后端差异

**3. 性能优化与移动端适配**
- 图片懒加载 + 渐进式模糊（IntersectionObserver），减少首屏图片请求 70%+
- 下拉刷新从固定 800ms 等待优化为数据驱动，感知速度提升 60%+
- 完成 **iPhone 全系列适配**：安全区（Home Indicator）、灵动岛（Toast 位置）、键盘弹出输入框自动上移
- 实现左滑手势导航、下拉刷新带阻尼动画等移动端交互，接近原生 App 体验

**4. CI/CD 与部署**
- 配置 **GitHub Actions** 自动化流水线，push 到 main 分支自动构建部署到 GitHub Pages
- 构建时间 < 1 分钟，零运维成本

### Q2: 说一个你印象最深的 Bug / 技术难点？

**推荐回答：照片上传的原子性问题**
- 问题：照片上传涉及 Storage 文件 + 数据库记录两个操作，任何一步失败都会导致数据不一致
- 分析：两种失败场景——先存文件写库失败（孤儿文件）、先写库存文件失败（幽灵记录）
- 方案：删除时先删 DB 再删 Storage，接受最终一致性；上传时先存文件再写库，写库失败回滚删文件
- 延伸：还可以讲内存泄漏、移动端适配等，每个都有具体数据

### Q3: 你是怎么做测试的？

**回答要点：**
- 功能测试：7 个模块全部手工走测，每个模块有明确的测试点
- 兼容性：Chrome/Safari/Firefox + iPhone 多款机型
- 专项测试：内存泄漏、数据一致性、存储持久化、移动端交互、性能、类型安全、边界条件
- 举例子：比如发现 URL.createObjectURL 内存泄漏——怎么发现的（上传几张照片后内存涨）、怎么定位的（代码审查 + 浏览器 Memory 面板）、怎么修复的（3 处全部补上 revoke）
- 数据说话：总共发现修复 15+ 个问题
